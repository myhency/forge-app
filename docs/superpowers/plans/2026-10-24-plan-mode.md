# Plan Mode (Plan 56A) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** When Claude proposes a plan, show it rendered in a `계획` dock panel and answer it with a plan card (`거부`, `수정…`, `수락`, `수락 및 자동 모드`, `⌄` menu) that sets the session's mode.

**Architecture:** `ExitPlanMode` already reaches Forge as a permission request whose `input.plan` is the plan. A plan card replaces the generic permission body when that text exists (the same way the workflow card does). A refusal gets an optional reason that travels port → wire → sidecar. The panel and the chat row read the plan from the pending request or from the transcript's `ExitPlanMode` call (`Item::Plan`, built like `Item::Workflow`), so no plan store is added.

**Tech Stack:** Rust (Dioxus, hexagonal crates), TypeScript sidecar (vitest), the real Claude Agent SDK for the spike and the window check.

**Spec:** `docs/superpowers/specs/2026-10-24-plan-mode-design.md`. Observations: `docs/superpowers/roadmap/observations.md`, Rounds 27 and 29.

## Global Constraints

- Strings go through `tr!` with Korean entries in `crates/forge-shared/src/ko.rs`; the Korean texts are the ones in the spec: `Claude가 계획을 제안했습니다`, `계획 열기`, `수락`, `수락 및 자동 모드`, `수락 및 편집 허용`, `수정…`, `거부`, `무엇을 변경해야 하나요? (선택사항)`, `뒤로`, `수정`, `계획 제안됨`, `계획`.
- Keys are matched by physical key (`code`), never the character (Korean input method). `Esc` opens `수정…`; no key accepts a plan; plain digits do nothing on the plan card.
- Mode mapping: `수락` → `default`, `수락 및 편집 허용` → `accept_edits`, `수락 및 자동 모드` → `auto`.
- `거부` and `수정` refuse without interrupting the turn, so Claude stays in plan mode and replies.
- A malformed `ExitPlanMode` request (no `input.plan` text) falls back to the generic permission card.
- Branch `plan-56`. Merge to `master` is the user's call.

## Review Focus

- `input.plan` missing, empty, or not a string on a request: the generic card still shows and can be answered (Task 3 test).
- `수정` with empty or whitespace-only text: the default reason is sent, never an empty deny message (Tasks 1 and 3 tests).
- Korean input method: `Esc` and `⌘↩` match by `code` while a composition is active (Task 3 test with `code` set and a different `key`).
- A second `ExitPlanMode` arrives after the first was answered: the panel shows the newer plan (Task 4 test on `latest_plan`).
- A reopened session whose transcript holds a plan but no live request: the row and the panel still show it (Task 3 and 4 tests).
- Mode change refused by the SDK: the session keeps running and the setting error shows (Task 1 spike decides the mechanism; Task 5 keeps the existing `setting_failed` path).
